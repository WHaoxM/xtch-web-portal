# Agent Rule Maintenance

本文件定义如何把重复错误和稳定经验沉淀为长期上下文。目标是让同类错误越来越少，而不是让规则越来越多。

## 何时更新规则

用户纠正 Agent 后，先判断这次纠正是否会重复影响未来任务。

可以沉淀：

- Agent 反复犯的错误。
- 项目特殊规则。
- 用户长期稳定偏好。
- 内容事实和证据边界。
- 常见任务流程。
- 多 Agent 协作机制。

不沉淀：

- 某次任务的临时目标。
- 某次页面的中间方案。
- 已经过期的调试过程。
- 一次性审美意见。
- Agent 自己的猜测。
- 代码里一眼能看出来的事实。

## 准入评分

| 维度 | 问题 | 通过标准 |
|---|---|---|
| 重复影响 | 未来是否会反复影响判断？ | 至少可能复用两次 |
| 具体性 | 能否指导明确行动？ | 能写成动作或判断规则 |
| 证据 | 是否有来源？ | 来自仓库、文档、用户确认或权威资料 |
| 可验证 | 能否检查是否遵守？ | 能通过阅读、命令或截图验证 |
| 维护成本 | 是否容易过期？ | 高波动内容只放链接或路由 |

建议：满足 3 项以上才进入长期上下文；涉及事实和业务边界时必须有证据。

## 路由规则

| 规则类型 | 目标文件 |
|---|---|
| 每次任务都必须遵守 | `AGENTS.md` |
| 项目入口、命令、目录、文档地图 | `docs/agent-context.md` |
| 某类任务流程 | `docs/agent-workflows.md` |
| 当前任务交接状态 | `docs/agent-progress.md` |
| 多 Agent 分工和阻塞 | `docs/agent-task-board.md` |
| 用户确认门禁 | `docs/agent-manual-gates.md` |
| 验证方式 | `docs/agent-verification.md` |
| 外部参考 | `docs/agent-references.md` |
| 高频小坑 | `docs/agent-gotchas.md` |
| 内容和资源来源 | `docs/content-resource-map.md` |
| 业务语言和产品边界 | `CONTEXT.md` |

## 规则写法

优先使用正向、具体、可验证的表达。

```md
差：不要乱改样式。
好：视觉改动先确认影响页面，并检查桌面和移动端布局。

差：不要编造内容。
好：路线事实先查 `docs/content-resource-map.md` 指定来源；来源不足时标注不确定。
```
